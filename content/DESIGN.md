# Rhue design notes

How Rhue fits together and why things ended up the way they did, milestone by milestone.

## Pipeline

```
source -> rhue-lexer -> rhue-parser -> resolver -> fold + codegen -> Proto tree -> rhue-vm
             tokens          AST        bindings,    (rhue-compiler)  (one per       frames,
                                        captures                      function)      upvalues
```

`rhue-common` (spans, diagnostics) sits under every crate. `rhue` is the embedder-facing facade, and `rhue-cli` is the binary.

## Key decisions

- **Register VM, 32-bit instructions.** The opcode is in the low byte, followed by `A`, `B` and `C` (8 bits each); `Bx`/`sBx` take 16 bits. Arithmetic has register-register and register-constant (`ADDK`…) forms.
- **One arithmetic function.** `rhue_bytecode::arith` is used by both the constant folder and the VM, so folded and run results are bit-identical. Tests run every case both ways.
- **Luau semantics.** f64 numbers; `//` is floor division and `%` takes the divisor's sign; division by zero gives inf or NaN; `tostring`-compatible number formatting; Luau error wording.
- **Spans everywhere.** Tokens, AST nodes and every instruction carry byte spans. All errors are `Diagnostic`s rendered by ariadne.
- **Bounded recursion.** Parse depth is capped at 1000, including left-associative chains, and the deep paths run under `stacker::maybe_grow`, so they're safe on small threads.
- **Resolver pass.** Every name occurrence gets a dense `NameId` from the parser. The resolver maps each one to `Local(id)` or `Global` in a side table, and enforces `break`/`continue` placement and Luau's `repeat … continue … until` rule.
- **Jump lists for conditions.** `cond_jump(e, when)` compiles conditions straight to compare+`JMP` pairs. `and`/`or`/`not` compose the lists, so conditions short-circuit without creating booleans.
- **Locals in registers.** Locals sit at the bottom of the register window, with temporaries above them. An `and`/`or`/if-expression assigned to a live local goes through a temporary, so the local isn't overwritten before it's read.
- **Interned UTF-8 strings** in a generational-handle heap; `Value` stays `Copy` and 16 bytes. Escapes that produce invalid UTF-8 are compile errors (a deliberate deviation from Lua's byte strings).
- **Instruction limit.** `Engine::set_instruction_limit` stops runaway scripts. Since M7 the budget is charged at backward jumps (by the distance jumped) and at calls, not per instruction; straight-line code is bounded by its length, so every loop and recursion is still stopped, and the count is approximate.
- **Calls without host recursion.** Lua-to-Lua calls push a `Frame` on a heap-allocated stack rather than recursing in Rust. Arguments already sit where the callee's parameters live, and results are copied down to the callee's slot. Depth is capped at 10,000 frames (`stack overflow`), however small the host thread's stack is.
- **Lua-style upvalues.** Captured variables stay in registers while their scope is live (*open* upvalue = stack index). `CLOSE`, or returning from the frame, moves them into a shared cell (*closed*). The resolver marks captured locals, so `CLOSE` is emitted only where needed: at scope exit, before `break`/`continue`, before each `repeat` iteration, and per numeric-`for` iteration (each iteration gets a fresh variable, as in Luau).
- **Per-prototype sources.** Every `Proto` carries an `Rc<SourceFile>`. A runtime error inside a function defined by an earlier `eval` renders against that earlier source, with a traceback in which repeated recursive frames collapse into one line.
- **Tables.** An array part for keys `1..n` (sequential inserts stay there and pull following keys over from the hash part) plus an insertion-ordered hash part (a linearly searched vector up to 8 entries, an `IndexMap` beyond, since M7). Assigning nil leaves a tombstone, so clearing fields during `pairs`/`next` is safe, as Lua guarantees. Number keys are normalised (`-0` is `0`); nil and NaN keys are errors.
- **Mark-and-sweep GC** over generational slabs (strings, tables, functions, upvalue cells, userdata). It marks with an explicit worklist, so a 200,000-long linked list doesn't overflow anything. Collection happens only at safe points: right after an instruction that can allocate (since M7). The intern map is weak, and the threshold is twice the surviving heap. Handles returned to the host hold a `Pin`, so they survive collection. A stress mode collects before every instruction, and the M3/M4 suites and a property test run under it.
- **`pcall` without re-entering the interpreter.** `pcall` marks the frame it starts as *protected*. A raised error unwinds frames, closing their upvalues, until the protected one, and its caller receives `false, value`. Errors carry Lua values (`error({code = 1})`), and string messages get Lua's `file:line:` prefix (`error(msg, level)` respected). The instruction limit can't be caught, so a host's budget always holds.
- **Re-entrant VM (M5).** Natives receive a `NativeCtx` holding the whole VM, so they can call functions, including scripts. Each call into the VM runs its own dispatch loop with a *boundary*: the frame count when it started. `RETURN` and unwinding stop there instead of popping the caller's frames. Once a native reaches the whole VM (to call a function, say), the Lua frame that called it is parked in `frames` (natives that only touch the heap skip this), so the collector roots it (its varargs included) and tracebacks run through the native. Errors cross natives unchanged as `NativeError::Rethrow` (same value, same traceback, still uncatchable if it's the instruction limit). Nesting is capped at 200 natives, and each re-entry into the VM runs under `stacker::maybe_grow`. This enables `table.sort` comparators (with a merge sort that never panics on an inconsistent comparator), `xpcall` and `pcall(pcall, …)`.
- **Typed natives (M5).** `Engine::register(name, f)` accepts closures or `fn` items of up to 8 parameters. Parameters are `FromArg`: any `FromValue` type takes one argument, and a trailing `Variadic<T>` takes the rest. Results are `IntoValues` (a value, `()`, a tuple), or a `Result` whose error raises a script error. A first parameter `&mut Context` gives access to the VM. A marker type parameter (`IntoNative<Marker>`) tells the arity and context variants apart, and Rust infers it. Conversions are strict, like a typed signature: no number↔string coercion, and integers must be integral and in range.
- **Userdata (M5).** A fifth heap kind holds an `Rc<dyn Any>` (an `Rc<RefCell<T>>`) plus a type id. Each type has methods, getters and setters that the VM consults on `obj.x`, `obj.x = v` and `obj:m()`. `#[derive(UserData)]` turns named fields into properties (`readonly`, `skip`, `name = "..."`), and `register_type::<T>()` adds methods and static functions (`T.new`). A method holds a mutable borrow, so touching the object again from a callback is a script error, not a panic. Rust holds objects as `Ud<T>` (shared) or takes a clone of `T`.
- **Fx hashing.** Table hash parts, globals and userdata member maps hash handles and number bits with an Fx-style hasher instead of SipHash (about 20% faster native-heavy code). String contents in the intern map use foldhash, seeded randomly per heap (M7).
- **Gradual types (M6).** The parser accepts Luau's type syntax everywhere (annotations, `type`/`export type` aliases with generics, generic functions, `T?`, unions, intersections, table and function types, singletons, `typeof`, `::`), and the compiler erases it (a cast is a parenthesised expression, so it truncates multiple values). `rhue-types` checks a resolved chunk in one pass when its directive (or the engine's default) asks: `--!strict` infers local and result types and rejects unknown globals and possibly-nil uses; `--!nonstrict` treats anything unannotated as `any`. Subtyping is structural, with covariant table fields (simpler than Luau's read/write variance), width subtyping, and coinduction for recursive aliases. Generic arguments are inferred from arguments; callbacks are typed by the parameter they fill. Narrowing applies to locals and field paths (`p.next.value`) and is dropped where it could be stale: on assignment, for locals a loop body assigns, and inside nested functions. Host functions and userdata are declared to the checker from their Rust types (`luau_type()` on the conversion traits). A property test runs every random strict program the checker accepts and requires that none fails with a runtime type error.
- **Performance (M7).** 1.3–1.8× faster than M6 on every benchmark in `bench/` (run with `cargo run --release -p rhue --example bench`). The dispatch loop keeps code, constants, base and pc in locals and indexes registers through a fixed `&mut [Value; 264]` window (no bounds checks for `u8` operands). Per-instruction *inline caches* (`Proto::cache`) remember where GETFIELD/SETFIELD/SELF/GETGLOBAL found their key. EQK/LTK/LEK/GTK/GEK compare against constants, and every comparison takes its following JMP itself. Hash parts of up to 8 entries are a linearly searched vector. Frames are 64 bytes (one `Rc<LuaClosure>`), RETURN moves results in place, open upvalues are a sorted `Vec`, and internal calls and natives return `Rets` (a `SmallVec`), so most calls allocate nothing; the typed embedding layer converts arguments lazily. `f64::floor` is replaced by an exact cast-based version.
- **Bytecode verifier (M7).** `rhue_bytecode::verify` checks opcodes, register bounds (`max_stack` ≤ 250, including registers above `R(A)`), constant indices and types, jump targets (never a DATA word), compare+JMP and SETLIST+DATA pairs, the `top` protocol, closure captures, and that a main chunk has no upvalues. The compiler verifies its output (panicking in debug builds), `Engine::run` verifies other prototypes once, and a fuzz test runs randomly damaged bytecode that still verifies: none may panic the VM.
- **Metatables (M8).** Every table has an optional metatable; strings share one whose `__index` is `string`. The fast paths stay as they were: an instruction falls to `meta.rs` only when its operands aren't plain (a missing key in a table with a metatable, arithmetic on a non-number, a call of a non-function). GETFIELD and SELF resolve the common class case, a one-level `__index` table, inline. `__index`/`__newindex` chains stop at 100 links. `__eq` is only asked about two tables that aren't raw-equal; `__lt`/`__le` work for mixed operands; `__call` shifts the callee into the first argument everywhere a call happens (CALL, TAILCALL, `pcall`, hosts' `call_value`). `__metatable` protects a metatable from `getmetatable`/`setmetatable`. Luau's `__iter` drives generalized `for`.
- **Metamethods in the dispatch loop (M9).** A Lua metamethod is an ordinary call frame placed just above the calling frame's registers (`Vm::meta_call`). When it returns, its first result goes straight to the instruction's destination register (its `ret_to` points there), or, for `__eq`/`__lt`/`__le`, a `cond` flag on the frame makes RETURN decide the comparison's jump in the caller. `__newindex` frames want no results. A native metamethod runs at once; a callable table runs through its `__call`, also in the loop. So metamethods cost a call, nest as deep as calls (`stack overflow`, not the native-depth limit), show in tracebacks, and can yield. `__iter`, `__tostring`, and metamethods reached from natives (`table.sort`'s default `<`, say) still run nested.
- **Typed metatables (M8, M9).** `TableType` carries an optional metatable: a live link to a local's type (so methods added to a class after `setmetatable` are seen) or a snapshot. Field lookups fall through `__index` (tables, chains, or a function's result type), assignments to unknown fields go through `__newindex`, operators and calls use the metamethods' result types, and `T.__index = T` marks a class. Since M9, `self` in a class's `:` methods is an instance: the checker records what the class's constructors return (any function on the class returning a table whose metatable is the class), and `self` gets those fields plus the class's methods through `__index`. It is `open`: fields only other methods add read and write as `any`, since one method can't see what the others add. Before any constructor has been checked, `self` is `any`.
- **Coroutines (M9).** A `Thread` heap object (`Value::Thread`) holds a coroutine's value stack, frames and open upvalues while it isn't running; the running thread's state lives in the `Vm`, and `resume` swaps states (the resumer waits as `normal`, rooted). The coroutine runs in a nested dispatch loop on the Rust stack. `yield` is a special native handled by `call`: it records where its results should go and returns a yield signal that the coroutine's base loop catches, pushing its frame back onto the coroutine's frame list; the next resume pops it and places the resume arguments there (setting `top` for open results), so a yield can sit inside `pcall` frames, metamethod frames or a tail call. A yield is allowed only at the nesting depth the coroutine was resumed at (`Vm::depth`, counting nested interpreter loops), so a yield from inside a native's callback raises "attempt to yield across a C-call boundary" instead of needing to unwind Rust frames. Open upvalues name their thread (`Upvalue::Open { index, thread }`), so a closure made in a coroutine can read its locals from outside while the coroutine is suspended; an open upvalue keeps its thread alive. Errors kill the coroutine; uncatchable ones (the limits) propagate through `resume`. Resumes nest at most 200 deep. Hosts use `Context::create_thread`, `resume` and `thread_status`; the checker knows `thread` and the library's types.
- **Tail calls (M8).** An unparenthesized `return f(...)` compiles to TAILCALL (always followed by `RETURN A 0 1`, which the verifier checks). A Lua callee replaces the current frame, so tail recursion runs in constant stack; a native callee is called normally. Each frame keeps a small trail of the last two frames it replaced plus a count of the rest, so tracebacks read "`a` (tail call)" and "(after N more tail calls)". The instruction limit still stops `local function f() return f() end`.
- **String interpolation (M8).** Backtick strings lex as one token; the parser splits them into text and holes, parsing each hole as an expression with spans pointing into the original string. INTERP concatenates `tostring` of a run of registers (honoring `__tostring`). `{{`/`{}` are errors, `\{` escapes a brace. The checker types the result as `string` and checks every hole.
- **Memory limit (M8).** `Engine::set_memory_limit` caps the bytes the collector accounts for. When an allocation pushes the heap over, the VM collects; if it's still over, it raises "not enough memory", which `pcall` can't catch (like the instruction limit). Big single allocations (CONCAT, INTERP, `string.rep`, `table.create`, `table.concat`) check their size before building, and natives can call `reserve`. The accounting is approximate (handle-heap sizes, not allocator bytes), so treat the limit as a budget, not an exact cap.

- **Patterns (M10).** `pattern.rs` is a port of Lua 5.4's `lstrlib.c` matcher: recursive backtracking over bytes with a depth limit ("pattern too complex"), up to 32 captures, the same error messages. `strpat.rs` builds `find` (plain search when the pattern has no specials or `plain` is set), `match`, `gmatch` (a native closure holding the subject, pattern and position) and `gsub` (string replacements with `%0`-`%9`, tables read raw, functions called through `NativeCtx::call`) on it. Captured text that cuts a multi-byte character becomes U+FFFD. A property test compares `find` with the `regex` crate on random patterns without alternation, where Lua's backtracking and leftmost-first semantics agree.
- **utf8 and os (M10).** `utf8.char/codepoint/len/offset/codes` follow Lua 5.4 (no `charpattern`: its bytes aren't valid UTF-8, and Rhue strings are). `os` is only `time`, `clock` (seconds since the VM was made), `date` (UTC, `*t` and `strftime`-style directives) and `difftime`: nothing that touches files, processes or the environment.
- **Modules (M10).** The facade keeps a `HostState` in the VM's host slot: the type environment, compile options, module sources, the host's loader, and `require`'s cache (a pinned VM table). `require` compiles a module (checking it as its directive asks), runs it once with its name as `...`, caches the result (`true` for nil), reports cycles from the stack of modules being loaded, and doesn't cache failures. For types, the checker records `require("literal")` calls whose module type it lacks; the engine checks those modules (compiling them and keeping the prototype for the later `require`), records their return types in the environment, and checks the chunk again. A module's type is `detach`ed: metatables held by locals become snapshots of those locals' types, so exported classes keep their methods and operators.

- **Formatter (M11).** `rhue-fmt` formats the token stream (comments recovered from the gaps between tokens), not the syntax tree, so comments, blank lines and the author's line breaks survive. Indentation comes from a stack of open frames (`function`/`then`/`do`/`repeat` blocks and brackets): frames opened on one line indent once, a line that starts by closing frames goes back to where they opened (and *retires* that opening line), continuation lines (ending or starting with a binary operator, `.`, `:`) get one extra level, and if-expressions are tracked so their `then`/`else` don't indent. Spacing is a table of token-pair rules, with two heuristics: a `:` followed by a name and call arguments is a method call (tight), otherwise an annotation (`x: T`); a `<` after a name whose matching `>` on the line encloses only type-list tokens is a generic. Only valid code is formatted, and the output is re-lexed and must match the input's tokens and comments exactly. A property test re-spaces real programs at random (never merging tokens) and requires identical output.
- **Analysis for tooling (M11).** `rhue_types::analyze_chunk` runs the checker in strict mode with recording on: every expression's and declared name's type by span, every name that resolves to a local (from `local_id`, so assignment targets count), and the members of the expression ending at a requested offset (`members_of`: table fields, metatable `__index` chains and classes, host types, the string library). Errors still come from a check in the chunk's own mode. `Engine::analyze` wraps it (resolving required modules first) with display strings, the resolver's local declarations, and the visible globals.
- **Language server (M11).** `rhue-lsp` is built on `lsp-server` and `lsp-types`. In M11 it used full-text sync and each request re-analyzed the document with a fresh engine (milliseconds for ordinary scripts; M13 made both incremental, below); its module loader reads open buffers first, then files next to the document. Completion patches the source so it parses (`obj.` gets a placeholder name and `()`), and asks for the members of the expression ending at the separator; name completion lists locals declared above the cursor (the resolver doesn't keep scope ends, so a local from a block that already closed can show up), globals and keywords. Positions are converted between byte offsets and UTF-16 columns. Hover and definitions need code that parses; mid-edit they return nothing.
- **Debug info (M12).** Each `Proto` carries `locals`: every local's name, register and the pc range where it's live (recorded by the compiler as scopes open and close). Lines come from the existing span table, through a lazily built line index on `SourceFile`.
- **Debug hooks (M12).** `Vm::set_debug_hook(mask, hook)` installs one hook for line, call and return events. The dispatch loop reads a single `hooked` flag per instruction; when set, `hook_due` decides whether this pc is a new line (a different line from the last event in this frame, or a backward jump onto the same one, so every loop iteration reports) or a return. Call events fire from the frame prologue, once per frame. To run the hook the frame is parked as if it were about to execute that instruction (so tracebacks and the stack walk see the right line), and the hook is taken out of the VM while it runs, so scripts it evaluates don't re-enter it. A hook's `Err` stops the script with an uncatchable error, like the instruction limit. `DebugCtx` walks frames (skipping natives' placeholder frames) and reads the locals live at a frame's pc, with shadowed names left out, and its closure's upvalues. Cost with no hook: about 3–4% more instructions on loop- and call-heavy benchmarks, 2% on method calls.
- **Debug adapter (M12).** `rhue-dap` owns the engine on one thread; a reader thread turns stdin into a channel of DAP messages. The debug hook is the scheduler: on each line it drains pending messages (breakpoint changes, pause), decides whether to stop (a breakpoint on this file and line, a step condition comparing stack depths, a pause), and if so sends `stopped` and serves requests (stack, scopes, variables, evaluate) until one resumes. Variable references are handed out per stop and cleared on resume; tables expand through them. Evaluate resolves a name (locals, then upvalues, then globals) and a field path, without running code. The module loader records which file each module came from, so frames in required modules point at real paths.
- **Rename and signature help (M12).** Rename only touches locals (declaration and refs from the analysis). Rather than reasoning about scopes, it applies the edit, re-analyzes, and requires every name-to-declaration link to be the same as before (shifted by the edit), which refuses renames that would capture or be captured by another variable or a global. Signature help finds the innermost unclosed `(` with a small scanner (skipping strings, comments and nested brackets, counting commas), types the callee (for `a.b`/`a:b`, the member's type), and labels parameters with names from the function's definition in the document when there is one. Mid-edit calls are retried with a placeholder argument, then with a `)`.
- **Saved chunks (M13).** `Proto::to_bytes` writes a magic number and format version, the source name and text, then the prototype tree (code words, constants, spans as offset and length, register counts, nested prototypes, upvalue descriptors, locals), with LEB128 lengths. `Proto::from_bytes` only checks shape: every length against the bytes left (so a damaged length can't allocate wildly), UTF-8, nesting depth, flags, spans inside the text, no trailing bytes. Everything about whether the code is safe to run is left to the verifier, which `Engine::load` always runs; the verifier now also checks debug info (each span lies in the source, each local's register and pc range exist), because the debugger trusts it. Keeping the source text costs size (a chunk is roughly twice its source) but keeps error messages and debugging intact. Types aren't saved.
- **Incremental analysis (M13).** The server's unit of reuse is the engine: `Docs` keeps one per open document, and an engine remembers the types of every module it has checked, so typing in a file re-checks just that file. Each engine records which module files its loader read (both candidate paths, so creating the missing one counts); a change to a document drops the engines and cached analyses of the documents that read it, and the server republishes their diagnostics. Saves and watched-file events drop every engine that read a module. The latest analysis of each document is cached by its text, so the requests after a keystroke (diagnostics, hover, signature help) share one. Text sync is incremental (ranges in UTF-16).
- **Evaluation in a frame (M13).** `Debugger::eval(level, expr)` compiles `local <names> = ...; return <expr>` (falling back to `<expr>` as statements), where the names are the identifiers among the frame's live locals, then its upvalues (locals win), and calls it with their values. Values are copies, so assigning to a local changes nothing in the frame; tables are shared. The hook is out of the VM while it runs, so evaluation doesn't re-enter it. `rhue-dap` uses it for watch and console evaluation, breakpoint conditions and logpoint messages (`{expr}` parts); hovers stay on the read-only path evaluator, because a hover shouldn't call functions. Hit counts count hits whose condition held; a condition that fails to evaluate stops and reports the error.
- **`self` in plain tables' methods (M13 fix).** Since M9, `self` in `function T:m()` was T's own type when T wasn't a class. That rejected the common pattern where methods are copied into objects (`{ items = {}, add = T.add }`), including `examples/tables.rhue` under `--!strict`. Now it's T's type, open: known fields keep their types and others read as `any`. A test now type-checks every strict example (M14's flow typing then caught `examples/closures.rhue` calling two functions assigned only inside a loop; it now says `assert(first and last)`).
- **Generic type packs (M14).** A pack `T...` is a `GenericVar` with `pack` set, and it only ever sits in a variadic slot: a function's `...` (`FnType.variadic`) or a result pack's tail (`Pack.variadic`), so `(number, T...) -> T...` needs no new fields. `Subst` keeps a second map, pack variable to `Pack`, and applying it splices the bound pack into the slot (`(number, T...)` with `T... = (string, boolean)` is `(number, string, boolean)`; unbound is `...any`). A call binds a pack from the arguments past the fixed parameters (and their tail), unless unifying a callback already fixed it, in which case the extras are checked against it; unifying function types binds packs from the rest of a function's parameters and results. A value read out of a pack (`local a = ...`) is `unknown`. The parser accepts `T...` in generic lists, after `...:`, as the last element of a parameter list, and as a result; `T` used as a type or `U...` for a non-pack is an error.
- **Alias parameters and defaults (M14).** Aliases keep their parameters as written. A use matches arguments to type parameters, then pack parameters (given as `(A, B)`, `()`, `...T` or `T...`; an alias whose only parameter is a pack takes plain types as the pack, `Callback<number, string>`), and fills in defaults, resolved in the alias's own scope with earlier parameters bound (`type Pair<A, B = A>`). Defaults are checked where the alias is declared. Packs in an alias body are fresh pack variables substituted after resolving it. Defaults exist only on aliases (a function with one is a parse error), and parameters with defaults must come last.
- **Flow typing of `local x` (M14).** In strict mode, a local with no value and no annotation starts as `nil`; each assignment adds the value's (widened) type to its declared type and narrows it to the value. Narrowings now merge where an `if` joins: each branch that carries on (not `return`, `break`, `error`) contributes the narrowings in effect at its end, a missing `else` contributes what the conditions leave, and a key narrowed somewhere becomes the union (a branch that didn't narrow it contributes its declared type). `do` blocks keep their narrowings. Where one pass can't see everything, a flow local is `any`: read inside a closure (it may run after later assignments), assigned by one (from then on), holding a table (whose type grows with assignments to fields), or read in a loop that assigns it (an earlier iteration did); after the loop, its full union applies. The hover type of the declaration is the final union.
- **Types in saved chunks (M14).** Format 2 adds an optional types section: what the chunk returns and the globals it defines, as Luau type syntax written by `rhue_types::portable` from the detached export types and read back with `Env::parse_type`. Syntax can't say everything: a table with a metatable is written as its fields plus those of its `__index` table, with a method's `self` (an instance-typed first parameter) as `any`, because detached instance types are unrolled only a few levels and `self` (compared contravariantly) would demand a deeper one; metamethods are dropped; aliases and error types become `any`, as does a type that doesn't resolve in the loading engine. `Engine::load` declares the globals; `Engine::add_module_bytes` also records the module's type for `require` (and `require` runs the stored prototype). Format 1 still loads.
- **Upvalue cells (M15).** An upvalue is an `Rc<Cell<Upvalue>>` shared by the closures that capture the variable, as Lua's own `UpVal` objects are, instead of a slab entry with a generation check: `GETUPVAL` is one `Cell::get` and a match. Closed cells hold a `Value` handle, which owns nothing, so cells can't form reference cycles; the collector marks a closed cell's value through each closure that holds it, and open cells need no marking (their values are on a thread's stack, which is marked anyway). Their memory counts in their closures' size.
- **Constants per chunk (M15).** Loading a chunk converts the constants of its whole prototype tree once (interning strings) into a tree of `Constants` nodes mirroring `Proto::protos`; `CLOSURE` clones the child's node instead of converting again. Each closure keeps its flat constants slice (what the loop reads) and its node; the collector marks a node once per collection (an epoch stamp), however many closures share it.
- **A smaller dispatch loop (M15).** Moving `CLOSURE`'s body out of the loop into an `#[inline(never)]` function didn't just pay for the two changes above: it cut instructions on benchmarks that never make a closure (`loops` −6.3%), because the loop's register allocation improved. The first version, with the body inline, was 1–3% *slower* on those. Cold arms belong out of line.
- **Linear joins (M15).** M14's join merge snapshotted every live narrowing at every `if`, which made a long function with many narrowed locals quadratic (6,400 lines: 2.1 s, 25 billion instructions). Now each `if` and block keeps a touch log: each key that code inside it narrowed or forgot, with its type before. A branch reports end types only for keys it touched; for a key it didn't touch, its condition's refinement (or, failing that, an earlier condition's falsy refinement, or the type before the `if`) stands in. That file now takes 65 ms (632 million instructions). The checker's maps also use foldhash instead of SipHash (5% of checking a large ordinary file).
- **Checker fixes found while profiling (M15).** `t or {}` hints the `{}` with `t`'s type, and a hinted empty table literal takes the hint's indexer, so `for _, x in tags or {} do` iterates `{string}`. Iterating a union of tables iterates either one's keys and values.
- **Comparisons (M15).** `bench/compare` is a separate Cargo project (so the workspace doesn't build Luau): Luau through `mlua` (interpreter, optimization level 2) runs the benchmark scripts unchanged, since they're Luau syntax; Rhai runs hand ports of six. Every result is checked against the script's `-- expect:` line.
- **Read and write access (M16).** A table property carries an `Access` (`ReadWrite`, `Read` or `Write`), parsed from Luau's `read`/`write` prefixes (contextual words: `read` is still a valid field name; on an indexer they're an error). Reading a write-only property or assigning a read-only one is an error. Subtyping follows the access the target asks for: `read` is covariant and needs the source readable, `write` is contravariant and needs it writable, and a plain property needs a plain one of the same type (invariant in effect, compared as before). The printer and the error explainer show the access.
- **Loops (M16).** A loop body that assigns a flow local is first checked in silent passes: errors, recorded types and references, narrowing layers and touch logs are rolled back after each pass, and the local's union grows with what the pass assigned. Up to three passes run until the unions stop changing (compared by their display), then the real pass runs with the settled types in effect at the top of the body; if they never settle the local is `any`, as before. `repeat ... until c` carries the body's end narrowings plus `c`'s truthy refinement past the loop, unless the body can `break`. The silent passes cost a loop body two to four checks, only for loops that assign flow locals.
- **Fields methods add (M16).** In a class's methods, assigning an unknown field on `self` (an open instance type) records it on the class's instance type, optional (it may be read before the method that sets it has run) and holding the union of the values assigned to it; later methods and code using instances see it. Only methods widen it: elsewhere, assigning to it is checked against that type. Fields the constructor gives keep their exact type, so `self.size = "x"` is still an error.
- **Exact types in saved chunks (M16).** M14 wrote types out unrolled and lossy; format 3 adds a list of alias definitions. The exporter names each recursive or class type it meets (the user's alias name when there is one, else the class's name, made unique against every name in the chunk) and writes a class as `type V = setmetatable<Fields, VClass>` plus `type VClass = { __index: VClass, ... }` with methods and metamethods, so `self` and operators survive. `setmetatable<T, MT>` is a built-in type function that gives a table type a metatable type. Loading parses the aliases into a closed scope (`AliasDef.closed`, a weak reference to it), which they resolve in wherever they're expanded, so they can't capture or be captured by the user's names; `Env::import` keeps the scope alive. If anything fails to resolve, loading falls back to M14's detached types. Formats 1 and 2 still load.
- **Fixes on diagnostics (M17).** `Diagnostic::fixes` holds suggested edits (title, spans and replacements) beside the human `help`; the CLI shows only the help, editors offer the edits. The checker adds them after the fact: an expression's check notes how many errors there were, and afterwards errors of the right kind at the right span get a fix. A missing member (`Key 'x' not found`, `Cannot add property 'x'`) gets the closest of `members_of` the object's type; an unknown global gets the closest global or earlier local; "could be nil" on `a.b`, `f()` or `a:m()` gets `assert(...)` around `a` or `f`. Closeness is optimal-string-alignment distance (a swapped pair is one edit), at most 1 for names up to four characters, 2 up to eight and 3 beyond; differing only in case always counts. `t["x"]` gets no fix, because the span to replace includes the quotes. `assert(x)` now returns `x`'s type without `nil`, as in Luau, so the fix checks.
- **Outlines (M17).** `rhue::outline(source)` parses and resolves, without checking, and walks the tree once. That gives symbols (nested by what they're defined on), a token per keyword, literal and name, classified by what the resolver says it refers to and how it was declared (and a string token split around interpolation holes), `local m = require("m")` bindings, every `x.f`/`x:f()` on a local or a `require` call, and what the chunk returns: for `return M`, the fields given in `M`'s constructor and by top-level `function M.f()`/`M.f = ...`; for a returned table literal, its keys, pointing at the local when the value is one. Outlines are cheap enough to compute for every file in a workspace, and the server caches them by text.
- **Inlay hints (M17).** The checker now records each function's final type at its body's span. `Analysis::hints` walks the tree for unannotated locals (except values whose type is obvious: literals, functions, casts), loop variables (except `_`), parameters (except the implicit `self`) and functions without a return annotation, and reads the recorded types (the last recorded for a span, so a flow local shows its final union). `any`, `unknown` and errors aren't shown. A hint is insertable when its text parses as a type (a result pack is checked as `() -> pack`), which rules out displays such as "with metatable"; inserting every insertable hint in a file still type-checks (a test does it). A return hint goes after the `)` that closes the parameters, found by lexing the function's text and counting parentheses.
- **Semantic tokens (M17).** Types are keyword, string, number, variable, parameter, function, method, property, type, type parameter and namespace; modifiers are declaration and default library (globals every engine starts with). Tokens come from the outline, are made relative as LSP wants, and are split at line breaks (long strings). Comments are left to the editor's grammar. A file that doesn't parse still gets its keywords and literals.
- **Across modules (M17).** A module field is a module path and a name. From a use (`m.f` where `m` is bound to `require("x")`, or `require("x").f` itself), the path is where `require` would find `x` from the using file, the same lookup the type checker's loader does. From the module's own definitions or its uses of the local it returns, the path is the file itself. Definition opens the field's definition in that file's outline; references scan the outlines of every `.rhue` file under the workspace folders (skipping hidden folders, `target` and `node_modules`), plus open documents, for uses that resolve to the same path (paths compare after canonicalizing, so `a/../b` matches). A field whose value is a local (`return { f = f }`) lists both the field's uses and the local's.
- **Buffers (M18).** `Value::Buffer` is a new heap kind: a slab of `Box<[u8]>`, fixed size, with no references for the collector to follow. It can be a table key (by identity), is pinned and lifted like the other handles (`rhue::Buffer`), and counts its bytes against the memory limit (`create` and `fromstring` check before allocating). The checker knows `buffer` as a host type with no members, like `thread`, and narrows `type(x) == "buffer"` to it. Accessors follow Luau: zero-based offsets, little-endian, bounds-checked (`buffer access out of bounds`), integers truncated and then wrapped to their width, `copy` within one buffer handling overlap. Rhue strings are UTF-8, so `string.pack`/`unpack` are left out (their output is arbitrary bytes), and `buffer.tostring`/`readstring` refuse bytes that aren't UTF-8.
- **Frozen tables (M18).** A `frozen` flag on `Table`. `Table::set` checks it first (the error is on a cold path) and `set_existing_str`, the field-store fast path, declines so that `set` reports it; the library functions that edit tables directly (`insert`, `remove`, `sort`, `clear`, `setmetatable`) check before starting. Writes that go to `__newindex` aren't writes to the table, so they still run, as in Luau. `table.clone` copies the table (and keeps its metatable, unless that's protected); `table.clear` now keeps the metatable too, which it used to drop by replacing the whole table.
- **`debug` (M18).** A native reaches the stack after `ctx.vm()` parks its calling frame in the VM's frame list; `debug.info` and `debug.traceback` read that list (skipping placeholder frames) or, for another coroutine, the frames saved in its thread. Level 1 is the calling Lua function and 0 the native itself, as in Luau; tracebacks use the same text as runtime errors, tail calls included.
- **The cost of a new value kind (M18).** Adding `Value::Buffer` (and a matching table key) cost 1.1–1.5% of instructions on table-heavy benchmarks, from hashing and comparing keys with one more variant and from `Table::get` no longer being inlined into the dispatch loop (forcing it back in was slower). The collector now keeps its mark vectors between collections; allocating and freeing them each time was itself costing up to 4% (on `classes`) where collections are frequent, because freeing the large vectors set off glibc's free-chunk consolidation.
- **Natives that yield (M19).** A native can return `NativeError::Yield(values)` (`ScriptError::yield_with` in the embedding API). When the dispatch loop called it directly, that's handled exactly like `coroutine.yield`: the coroutine suspends at the call, the values go to the resumer, and what the next resume passes is placed where the native's results go. Anywhere else (a native called by another native, by `pcall`, as a metamethod handler) it becomes the error yielding there would give, so no Rust frame is ever suspended. `pcall(native)` runs the native nested, so it can't yield, as with `pcall(coroutine.yield)`; `pcall(function() native() end)` can.
- **Tasks and the scheduler (M19).** `Engine::spawn` is a coroutine plus a shared state cell, so a `Task` reports where it stopped whoever resumed it (the host, or the scheduler from `task.wait`). The `task` library is opt-in (`open_tasks`) and lives entirely in the embedding crate: a scheduler with a clock, timers ordered by due time then creation, and a deferred queue, shared by its natives through an `Rc`. `task.wait` records a timer for the running coroutine and yields; `step(dt)` advances the clock, resumes the timers that were due when it started (so `task.wait()` means the next step, never this one) and then drains deferred threads, up to 10,000 a step so self-deferring code can't hang the host. Errors from scheduled resumptions are collected and returned by `step` rather than raised. A thread resumed by anything but the scheduler while it waits isn't tracked; when its timer comes due it's skipped unless it's suspended.
- **Environments (M19).** A Lua closure carries an optional environment table. `GETGLOBAL` checks it before the inline-cached lookup and, when set, reads the table and falls back to the VM's globals; `SETGLOBAL` writes the table (so a frozen environment is read-only). `CLOSURE` copies the parent's environment, and the collector marks it. Reading `f.cl.env` inside the two opcodes rather than once per frame matters: holding it in a local across the dispatch loop cost up to 1.7% (register pressure); read where it's used, it costs at most 0.4%. For type checking, the checker's script-defined globals are swapped for the engine's plus the environment's own while a chunk compiles, and what the chunk defines is recorded only in the environment.
- **serde (M19).** `rhue::serde` (behind the `serde` feature) maps values the way JSON does: structs and maps to tables, sequences to array tables, externally tagged enums, bytes to buffers. A table reads back as a sequence when its keys are exactly 1 to n; whole numbers below 2^53 deserialize through `i64`, so integer fields get serde's own range checks.
- **Vectors (M20).** `Value::Vector([f32; 3])`: the tag and three `f32`s still fit the 16-byte `Value`, so vectors are plain values like numbers, with nothing for the collector to do. Arithmetic on them goes through the existing out-of-line path for anything that isn't two numbers (`arith_meta` → `arith_values`), before any metamethod lookup, so the inline number fast path is unchanged; `-v` is handled in `unm_meta` and `v.x` in `index_meta` (component names `x y z` and `X Y Z`). The allowed combinations are Luau's: componentwise `+ - * / //` between vectors, and `v * n`, `n * v`, `v / n`, `n / v`, `v // n`; computed in `f32`. A vector is a table key by value (`Key::Vector`, its components' bits with `-0` as `0`; NaN is refused like a NaN number). `tostring` prints components at `f32` precision (`0.1`, not the `f64` it widens to), while `v.x` gives the widened number, as in Luau. In the checker, `vector` is a host class with read-only number properties, plus a rule in `binary_type` for the arithmetic (checked before metamethods) and in `-`.
- **Comparing keys by hand (M20).** Adding an array-holding variant to `Key` made its derived `==` slower, which showed up as +2.0–2.3% on `classes` and `methods` (small tables compare keys linearly). `Key::eq` is now written out: different variants are unequal at once, string keys compare inline, everything else is an out-of-line call. That made table-heavy code faster than before M20. The same treatment for `Value::eq` helped tables more but cost `loops` 5% through the dispatch loop's layout, so `Value` keeps the derived one.
- **The REPL (M21).** `rhue` with no arguments on a terminal uses rustyline. Its validator compiles the entry so far on a spare engine and asks for another line only when the parse error is about running out of input ("found end of input", an unterminated long string or block comment), so `x = )` is reported at once while `function f()` continues. A leading `local` (a plain `local a, b = ...` or `local function`) is dropped before running, since each entry is its own chunk and the local would otherwise be gone by the next one. Each entry is compiled as an expression first, falling back to a statement block. Results go through a small pretty printer: arrays then sorted names then other keys, nested strings quoted, three levels deep, cycles marked, `__tostring` respected, and wrapped onto several lines past 80 columns. `:type` calls `Engine::expression_type`, which checks `--!strict local __type = (expr)` with the session's declarations and reads the type recorded for `__type`. Piped input works the same way without the line editor, and exits non-zero if any entry failed.
- **The test runner (M21).** `rhue test` finds `*_test.rhue` and `*.test.rhue` (skipping hidden folders, `target` and `node_modules`), and gives each file a fresh engine with `test`, `describe` and `expect` installed and declared to the checker. The functions themselves are Rhue, a prelude compiled into the binary: `test` records a name and a function, and the runner calls each separately and catches its error, so one failing test doesn't stop the rest. Matchers raise with `error(message, 3)`, which puts the failure at the `expect` line in the test file; the runner drops the prelude's frames from the traceback before printing. Modules resolve from the test file's folder, then the working directory.
- **Table templates (M22).** A constructor whose fields have constant string keys compiles to `DUPTABLE A Bx` instead of `NEWTABLE`: `Proto::templates[Bx]` holds the array and hash sizes to reserve and the keys (constant indices), and the table starts with those keys present and nil. Tables already treat a nil value as a tombstone (counted, skipped by `next`, revived in place by a store), so a template is invisible except for where keys sit: each constructor `SETFIELD` then hits an existing slot through its inline cache instead of growing the hash part and searching it. Two rules keep insertion order exactly what the plain path gives: the template stops at the first computed key (`[k] = v`), and a field written as a literal `nil` stays out (it isn't stored, so its key goes in when first assigned). A field whose value only turns out nil at runtime keeps its slot, which is still a valid Lua order (Lua leaves `pairs` order unspecified). Templates are saved in chunk format 4 (flag 4 on a prototype); the verifier checks indices, that keys are distinct string constants, that the hash size covers the keys, and that sizes stay under 65,536. `Table::from_template` is kept out of line: inlined into the dispatch loop it cost `loops` 1.5% through code layout.
- **Cheaper calls (M23).** Per `fib` call the VM spent about 775 instructions. `RETURN` now moves up to three results by hand instead of through `copy_within` (a `memmove` call for one value); `close_upvalues` checks inline whether anything is open at or above the frame and only then calls the loop; `call` matches Lua closures first and hands the closure it found to `enter_closure`, instead of `enter_lua` looking it up again. `Frame` stays at 72 bytes: shrinking `pc`/`base` to `u32` and boxing varargs thinly would save a few instructions per call for a change to hundreds of lines.
- **Builtin fast paths (M23).** `Native::fast` is an optional `FastFn = fn(&mut Vm, &[Value]) -> Option<Fast>`, `Fast` being one result or two. `CALL` on a native with one, unprotected and with at most three arguments, copies them to a small array and writes the results straight to the caller's registers; `None` means "not the plain case" and the full native runs (so all errors, and anything with zero or many results, come from `stdlib`). Luau's `FASTCALL` is chosen by the compiler from global names and must check at run time that the environment wasn't modified; attaching the shortcut to the function value instead makes shadowing a non-issue and needs no compiler support. `fastcall::install` attaches them after `stdlib::install`: `type`, `rawequal`, `rawget`, `rawlen`, `setmetatable`, `getmetatable`, `next`, the `ipairs` iterator, `math.abs`/`floor`/`ceil`/`sqrt`/`round`/`sign`/`min`/`max`/`clamp`, and `string.len`/`byte`/`sub` (which also skips the full natives' copy of the string argument). A test runs each on about 40 argument lists both ways (`f(...)` and `pcall(f, ...)`, which always takes the full path) and requires identical results and messages.
- **Coroutine switches (M23).** A `yield` built an error-shaped `Thrown` with a fresh `SourceFile` (three allocations) and a message string; the source is now made once per thread and the message is empty (the signal is never shown). `resume_thread` moved each thread's `ThreadState` four times per switch (take, park, unpark, load); it now swaps the VM's fields with the parked state in place (`swap_state`), relying on a running thread's parked slot being empty.
- **Not done (M23): the register-window check.** Every instruction re-borrows `self.stack[base..base + REG_WINDOW]` as a fixed-size array, which costs two bounds checks (about four instructions). The stack never shrinks under a live frame, so `get_unchecked` would be sound, but the workspace forbids `unsafe_code` (a `forbid` lint in `Cargo.toml`), and a VM without `unsafe` is worth more than ~5% on tight loops.
- **Release readiness (M24).** Only `rhue` promises a stable API; the other crates say so on their front pages ("part of Rhue's implementation") but are published, since `rhue` depends on them. Every crate packages and builds from its packaged sources (`cargo package --workspace`, also run in CI). `rhue` warns on `missing_docs`; its crate docs carry runnable examples for each major area (embedding, types, sandboxing, modules and compiled chunks, tasks). The declared minimum Rust was 1.85, but the code uses let chains (stable in 1.88), and clippy's `incompatible_msrv` only covers library APIs, so the mismatch went unnoticed until checked; it's 1.88 now, a CI job builds on exactly that version, and clippy (now allowed to assume let chains) collapsed some nested `if let`s into them, which left every benchmark's instruction count unchanged. CI also runs each benchmark script once in release mode, since every script states its expected results: a cheap guard that an optimisation hasn't changed behaviour. The license field always said MIT OR Apache-2.0; the license texts are now in the repository, the MIT one in the name of "the Rhue contributors".
- **Async hosts (M25).** An async native is the same trick as `task.wait`: park something against the calling thread and yield back to whoever resumed it. Here the something is the future, in a list the drivers (`eval_async`, `call_async`, `run_until_idle`) poll every turn, so a bunch of them wait at once. When one finishes, the driver resumes its thread with `true, results...` or `false, error`, and a tiny Lua wrapper around the raw native returns the results or raises the error at the caller's line (the VM can't resume a coroutine *into* an error, and this keeps `pcall` working). An async call is only allowed in a thread the host resumed: in a script's own `coroutine.wrap` the yield would land in the script's resumer instead, so that's an error now, and the VM tracks which kind of resume a thread last had (`by_host`). The driver keeps the `task` clock on real time with the host's sleep function, and trusts that function's idea of when a deadline passed over `Instant::now`, since under a paused test clock the two disagree. Rhue doesn't pick a runtime and its futures aren't `Send`.
- **Interrupts (M25).** The instruction budget used to be one number, checked with a compare and subtract on back edges and calls. Now it's handed out in slices of 16k, and when a slice runs out a cold path checks an `AtomicBool` before refilling, so cancelling from another thread costs nothing in the loop. The slow path can't continue the instruction it interrupted (the register window is still borrowed), so it refills and re-runs the instruction, which is fine because every instruction charges before it changes anything. Every benchmark stayed within noise of M24. Interrupts can't be caught by `pcall`, and a driver waiting on a future registers a waker with the handle so it stops right away too.
